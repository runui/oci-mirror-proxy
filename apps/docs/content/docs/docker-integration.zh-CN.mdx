---
title: 自动配置 Docker
description: 接入本机 Docker Engine 或 Docker Desktop，并安全撤销配置。
---

本机 Linux Docker Engine 与 macOS Docker Desktop 使用相同命令，无需选择平台：

```sh
oci-mirror-proxy dockerd plan
oci-mirror-proxy dockerd apply
oci-mirror-proxy doctor
oci-mirror-proxy dockerd revert
```

这些命令从运行中的服务获取代理地址和仓库路由；使用 `--admin-socket` 选择非默认服务。容器部署请先导出服务信息，并为宿主机命令传入 `--server-info`，参见 [Docker 部署](/zh-CN/docs/docker#configure-the-hosts-dockerd)。客户端命令不会通过 `--config` 加载配置文件。

程序根据当前 Docker 连接自动识别环境。SSH/TCP 远程连接会在修改本机配置前被拒绝。Docker Desktop 根据 daemon 识别，不取决于镜像存储后端；无法识别的环境会明确报错，不会猜测配置路径。

## 部署与激活 [#deployment-and-activation]

macOS 下以普通用户运行主机 CLI，不使用 sudo，并确保 PATH 中有 docker。标准 Compose 使用 bridge 网络，仅将端口发布到主机 loopback；配置需要挂载整个可写目录。同网络中的容器仍可能访问无认证的 Registry API，避免与不可信容器共享网络。

macOS 集成会备份并合并 `~/.docker/daemon.json`，保留其他字段和 mirror，将代理放到首位。支持 Docker Hub，不会自动配置其他 Registry，也不要求关闭 containerd image store。

需要重启才能生效时，默认只保存配置并报告待生效。明确允许中断后执行：

```sh
oci-mirror-proxy dockerd apply --restart
```

需要 Docker CLI 支持 `docker desktop restart`。激活失败时，错误会区分已保存的配置与未完成的激活，备份仍可用于恢复。`doctor` 同时检查文件与 daemon 已加载的 mirror；API 检查成功并不能证明实际拉取经过了代理。

Linux 仍支持按存储后端配置、rootless 选项和 `--no-reload`。显式指定文件与存储后端可用于无运行中 Docker daemon 的配置生成，普通使用无需这些覆盖参数。修改 Linux 宿主机配置可能需要提权。

## 恢复 [#recovery]

移除代理前先撤销；需要重启时附加 `--restart`：

```sh
oci-mirror-proxy dockerd revert --restart
```

撤销仅移除当前配置中的目标代理条目，保留其他设置和后续修改，不恢复历史快照。与 `apply` 一样，代理地址来自选定的运行中服务或 `--server-info` 快照。备份和旧状态文件不参与判断。

只有实际变更才备份并原子替换，重复操作不重写文件。无效配置及操作期间检测到的外部修改会导致报错，`--force` 不绕过校验。每个目标文件使用独立操作锁；外部编辑器若不遵守锁，仍可能与最终替换竞争。多文件写入不是整体事务，失败时报告已修改文件及备份位置。进程崩溃可能留下 `.oci-mirror-proxy.lock` 操作锁，确认无其他配置操作后才能移除。重启可能改变内部网络 ID 和日志，配置恢复不等于虚拟机磁盘快照回滚。

## 已验证范围 [#verified-scope]

已在 Apple Silicon、Docker Desktop 4.95.0、Engine 29.8.2、containerd image store 上验证自动配置、重启、普通 Docker Hub 镜像名经受控上游下载真实层、诊断、重复应用及配置恢复（历史版本行为）。不据此承诺所有 Desktop 版本、其他 macOS 引擎、BuildKit 镜像源或所有公共上游的兼容性。工具不会自动升级 Docker Desktop。
