## 环境要求与镜像 [#requirements-and-image]

支持本机 Linux Docker Engine 或 macOS Docker Desktop 及 Compose 插件。统一 Compose 使用 bridge 网络，仅发布 `127.0.0.1:24817`。配置、生效和恢复参见[自动配置 Docker](/zh-CN/docs/docker-integration)。rootless 网络可能需要额外配置，参见 [Rootless dockerd](/zh-CN/docs/operations#rootless-dockerd)。

镜像可从项目的 Gitea 容器仓库获取：

```text
git.zmide.com/bin/oci-mirror-proxy:latest
git.zmide.com/bin/oci-mirror-proxy:v1.0.1
git.zmide.com/bin/oci-mirror-proxy:dev
```

镜像支持 `linux/amd64` 和 `linux/arm64`。`latest` 对应稳定的 `v*` 标签，版本标签也包含预发布版本，`dev` 跟随 `master`。生产环境建议固定版本标签或摘要。如果软件包是私有的，需先运行 `docker login git.zmide.com`。

Dockerfile 采用多阶段构建，运行镜像基于 `scratch`，仅包含静态 Go 二进制及系统 CA 证书，不含 shell，以 `65532:65532` 用户和组运行。

## 使用 Compose 启动 [#start-with-compose]

在项目根目录执行：

```sh
mkdir -p config
cp examples/config.docker.yaml config/config.yaml
# 非 root 容器需要能够原子替换配置文件。
sudo chown -R 65532:65532 config  # 仅限 Linux；macOS 保持当前用户所有权
sudo chmod 700 config
sudo chmod 600 config/config.yaml
docker compose pull
docker compose up -d --no-build
docker compose ps
docker compose logs -f
```

可在 `.env` 中指定镜像，也可导出同名环境变量：

```dotenv
OCI_MIRROR_PROXY_IMAGE=git.zmide.com/bin/oci-mirror-proxy:v1.0.1
```

也可以本地构建，无需拉取已发布的应用镜像：

```sh
OCI_MIRROR_PROXY_IMAGE=oci-mirror-proxy:local docker compose build
OCI_MIRROR_PROXY_IMAGE=oci-mirror-proxy:local docker compose up -d --no-build
```

初始配置有意不预设任何上游镜像源。使用前请添加真实镜像源；列表为空时，dockerd会回退到官方仓库：

```sh
docker compose exec oci-mirror-proxy oci-mirror-proxy upstream add \
  --id mirror-a --url https://mirror-a.example.com
docker compose exec oci-mirror-proxy oci-mirror-proxy status
curl -fsS http://127.0.0.1:24817/v2/
```

必须挂载**整个配置目录**，而非单个 `config.yaml` 文件：上游管理通过原子重命名保存配置，因此需要目录写权限。配置变更在重建容器后仍会保留。手动编辑时使用 `sudoedit config/config.yaml`，然后重载：

```sh
docker compose exec oci-mirror-proxy oci-mirror-proxy reload
```

健康检查查询本地管理套接字，仅检查进程是否响应，不检查上游可用性或宿主机 dockerd 配置。管理套接字位于私有 tmpfs 中，不暴露到宿主机。日志输出到 stderr；SIGTERM 会触发优雅关闭。不需要特权模式，也不需要挂载 Docker socket 或宿主机 Docker 配置。

<span id="配置宿主机-dockerd" />

## 配置宿主机 dockerd [#configure-the-hosts-dockerd]

启动容器**不会**自动让 Docker 使用代理。按[安装说明](/zh-CN/docs/installation) 在宿主机安装 CLI。先导出运行中容器不含敏感信息的服务信息，再将该快照传给宿主机 CLI，预览并应用接入配置：

```sh
docker compose exec -T oci-mirror-proxy oci-mirror-proxy server info --json > server-info.json
oci-mirror-proxy dockerd plan --server-info "$PWD/server-info.json"
oci-mirror-proxy dockerd apply --server-info "$PWD/server-info.json"
oci-mirror-proxy doctor --server-info "$PWD/server-info.json"
docker pull hello-world
```

Linux 上如需提权，请在配置命令前添加 `sudo`。macOS 上以普通用户执行；准备好中断 Docker 并使配置生效时，再为 `dockerd apply` 添加 `--restart`。

这些宿主机命令不需要访问容器内私有的管理套接字或配置文件。修改对外公布地址或仓库路由后，请重新导出快照。客户端命令的 `--config` 是已弃用且被忽略的兼容参数，不能用来选择容器配置。

不要再在宿主机启动第二个代理服务；使用安装脚本时不加 `--service`。手动配置与回滚方法见[运维指南](/zh-CN/docs/operations#setting-up-dockerd)。

容器内监听 `0.0.0.0`，宿主机仅发布回环端口，避免将无认证接口暴露到局域网。同网络容器仍可能访问此接口，不要与不可信容器共享网络。macOS 上保持配置目录归当前用户所有，主机 CLI 不使用 sudo；需要生效时显式使用 `--restart`。

认证镜像源引用的环境变量需通过 Compose `environment` 显式传入（只写入 `.env` 不会注入容器），也可挂载 Compose secrets 并使用 `file:/run/secrets/...` 引用。自定义 CA 文件应只读挂载，`tls.ca_file` 使用容器内路径。挂载文件必须允许 UID 65532 读取。不要将密钥写入镜像或构建上下文。

<span id="更新与停止" />

## 更新与停止 [#update-and-stop]

```sh
docker compose pull
docker compose up -d --no-build
docker compose down
```

`down` 不会删除 `config/`。永久移除代理前，请在宿主机执行 `oci-mirror-proxy dockerd revert --server-info "$PWD/server-info.json"`，确认变更生效后再停止容器。Linux 上按需使用 sudo；macOS 上不使用 sudo，并添加 `--restart` 使恢复后的设置生效，这会中断运行中的容器。撤销操作只从当前 Docker 配置中移除本代理条目，不恢复历史快照。

<span id="本地构建" />

## 本地构建 [#local-builds]

运行测试并构建本地镜像：

```sh
docker build --target test .
docker build -t oci-mirror-proxy:local --build-arg VERSION=dev .
```
